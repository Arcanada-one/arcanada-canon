# Расхождения между перепиской и ТЗ

Переписка — первоисточник намерения оператора. ТЗ — его переработка. Ниже места, где ТЗ
**отошло от прямой формулировки оператора**. Обоснование в ТЗ, как правило, дано и выглядит
разумно, но согласие оператора местами лишь косвенное. Правило экосистемы: конфликт источников
записывается и удерживается, а не разрешается молчаливым выбором по умолчанию.

## Критичные — решать до начала реализации

### П-1. Как агент находит обязательный Canon
- **Оператор:** «агенты по-прежнему находят нужные паки в базе знаний **через векторный поиск**, там через графовый поиск, как мы это делаем».
- **ТЗ v0.1, решение №2:** обязательный Canon **не ищется** вектором — детерминированное разрешение по точным идентификаторам.
- Ответ пометил это как «самое важное решение» и открыто заявил о корректировке. **Явного подтверждения оператора в переписке нет.**
- Аргумент ТЗ силён (вероятностный поиск может не вернуть запрет в top-k), но решение противоположно букве.

### П-5. Автономия агентов: «пушат» против «только proposal»
- **Оператор:** «я хочу, чтобы агенты… складывали, присоединяли, компилировали и всё, и **пушили**».
- **ТЗ §10.4 + AC-020:** агент по умолчанию создаёт **только proposal/draft**, не может активировать Universe/Project policy без review.
- Ответ подал это как соответствие идее оператора. Буквально — это сужение запрошенного цикла.

### П-6. Human gate против DEC-AUP-0010
- **Переписка §12 п.9:** «**Human gate:** фундаментальные политики уровня Universe и Galaxy требуют утверждения владельцем».
- **Действующее правило хоста:** гейтов на оператора нет (DEC-AUP-0010); «awaits operator» запрещено, человеческое ревью становится слепым агентским.
- Прямой конфликт с записанным решением экосистемы. Разрешает консилиум + `DEC-AUP-00xx`, **не** реализующий агент.

### П-11. Три несогласованных словаря терминов
| Источник | Термины |
|---|---|
| переписка, реплика 1 | Source Canon / Normalized Canon / Resolved Runtime Context |
| ТЗ v0.1 | Scope Pack / Overlay Pack / Context Snapshot |
| ТЗ v0.2–v0.3 | Canon Bundle / Context Capsule / Context Snapshot |
Перекрывающиеся понятия под тремя наборами имён — гарантированная путаница при нарезке задач на агентов. Терминологию надо зафиксировать до Epic 1.

## Прочие расхождения

| # | Оператор сказал | ТЗ решило |
|---|---|---|
| П-2 | «ссылки идут в **папку**, где репозиторий» | логические `canon://` URI; путь в Git — не authoritative identity |
| П-3 | «на **продакшн сервере**, да? Или на сервере базы знаний» | сервер знаний; production-агенты не монтируют Git |
| П-4 | иерархия «**начиная от персональных пользовательских** до вселенной» | Actor Overlay — не потомок Project, а параллельная ось |
| П-7 | «должны получить **самый компактный канон**… один компактный канон» | v0.3: 8 разных представлений, «компактный Canon больше не один файл» |
| П-8 | «может быть **пять** агентов с разными ролями» | 7 seats: 3 компилятора + 2 аудитора + Consigliere + Verifier |
| П-9 | «мьюнир, наверное, это никак не касается» / «сразу же обновляться» | полная интеграция; pinned snapshot, обновление только явным `Rebase Canon` |
| П-10 | — | внутреннее противоречие ТЗ: `visibility: internal` используется, но словарь значений и маппинг в ACL нигде не определён |

# Открытые вопросы, оставленные первоисточником

1. **Уровни Talomnia не зафиксированы.** «там не будет такого, наверное, высокого уровня Вселенной… **может быть**, там уровни модулей». Верхняя граница ScopeMount не определена.
2. **Частота перекомпиляции.** «раз, может быть, в неделю максимум, или хотя бы не чаще раза в день» — оператор колеблется; каденс v0.3 им не подтверждён.
3. **Конкретные модели и провайдеры консилиума.** CouncilProfile задаёт только правила (≥3 семейства, ≥2 провайдера, ≤2 места на семейство). Портфель не выбран.
4. **Владелец Scope Registry.** ТЗ §5.2: «backend Control Arcana **или** отдельный Platform Registry» — выбор не сделан.
5. **Сервер знаний не назван.** Ни хоста, ни пространства — только роль «рядом со Scrutator».
6. **Воспроизводимость inference.** ТЗ честно фиксирует: без закрепления weights провайдером bit-for-bit повтор не гарантируется. Признанное ограничение, не решение.
7. **Пороги C/G/R/U → D.** Формула `D = max(...)` задана, числовые пороги — нет.
8. **Судьба существующих уставов Arcanada.** Миграция `documentation/mandates/`, `spaces/*/space.yml`, `CLAUDE.md` в Canon **не рассмотрена вообще** — ни в переписке, ни в ТЗ. Это наш собственный пробел, и он крупный.
9. **Muneral: ТЗ против боевого API.** ТЗ предполагает новые поля Work Item. Как это ложится на действующий Muneral — не рассматривалось. Измерено 2026-09-10: агентский ключ `mun_sk_` не может ни читать список задач, ни создавать их (401/404) — доступен только поиск по одному `legacyId`.
10. **`.diff` v0.2→v0.3 не передан** — объявлен в SHA256SUMS, физически отсутствует.
11. **Контрольная сумма промпт-бандла не сходится** — содержимое совпадает побайтово, отличается сам архив (см. `INDEX.md`).
